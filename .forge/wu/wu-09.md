# Add pan and zoom with touch gestures

## Outcome

Both GM and Player can pan the map by dragging with two fingers (or middle-mouse/right-click drag on desktop) and zoom with pinch gestures (or scroll wheel on desktop). The map renders at the correct zoom level and pan offset. All existing interactions (fog brush, token drag) continue to work correctly at any zoom/pan state. Coordinate transforms (screen ↔ image) account for the current viewport transform.

## Values

1. Gesture correctness — 1-finger = interact, 2-finger = pan, pinch = zoom. No mode toggle needed.
2. Coordinate accuracy — strokes and tokens must land exactly where the user points, regardless of zoom/pan.
3. Smoothness — zoom/pan must feel fluid, no visible lag or jitter.

## Context

- `public/js/canvas.ts` — `initCanvas()` creates a wrapper div with 3 stacked canvases (map, fog, preview). `sizeAll()` (line 79-91) computes a fixed scale factor from container size to image size. `screenToImage()` (line 173-178) converts screen coordinates to image coordinates using `fogCanvas.getBoundingClientRect()`. This is the primary file to modify — the wrapper needs a CSS transform for pan/zoom, and `screenToImage()` must account for it.
- `public/js/tokens.ts` — `initTokenLayer()` adds a 4th canvas to the wrapper. Has its own `screenToImage()` (line 43-49) and `getScale()` (line 37-41). Both must be updated to account for viewport transform.
- `public/js/gm.ts` — pointer event handlers (lines 199-231) for fog brush. `pointerdown` immediately starts drawing. Needs ~100ms grace period to distinguish 1-finger draw from 2-finger pan.
- `public/js/player.ts` — token drag on `pointerdown` (via tokens.ts line 107-121). Same grace period needed.
- `public/css/style.css` — `#canvas-area` (line 104-112) is a flex container with overflow hidden. The wrapper inside it needs `transform-origin: 0 0` and a dynamic `transform: translate(…) scale(…)`.
- `DESIGN.md` — gesture map: 1-finger = interact, 2-finger drag = pan, pinch = zoom. ~100ms grace period before committing to draw so second finger can arrive.

## Requirements

### 1. Viewport module (`public/js/viewport.ts`)

Create a module that manages viewport state and exposes:

```typescript
interface Viewport {
  // State
  readonly scale: number;    // current zoom level (1.0 = fit-to-container)
  readonly panX: number;     // horizontal offset in screen pixels
  readonly panY: number;     // vertical offset in screen pixels

  // Coordinate transform
  screenToImage(clientX: number, clientY: number): { x: number; y: number };

  // Attach to a container element — installs event listeners
  attach(container: HTMLElement, wrapper: HTMLElement, getImageSize: () => { w: number; h: number }): void;

  // Called when image changes (recompute base scale)
  resetView(): void;

  // Event: fires when transform changes (so canvas can update)
  onChange(callback: () => void): void;
}
```

**Zoom behavior:**
- Scroll wheel: zoom centered on cursor position. Scale factor: `1.1` per wheel tick up, `1/1.1` per tick down.
- Pinch gesture: zoom centered on the midpoint of the two touches. Scale = ratio of current pinch distance to initial pinch distance.
- Minimum zoom: fit-to-container (the base scale). Maximum zoom: 10x the base scale.
- Zoom formula: apply scale change, then adjust panX/panY to keep the focal point (cursor or pinch midpoint) stationary on screen.

**Pan behavior:**
- Two-finger drag: pan by the delta of the midpoint between the two touches.
- Middle-mouse drag (button === 1): pan by pointer delta.
- Pan is clamped so the image edges don't move past the container center (user can't lose the map).

**Touch gesture discrimination (~100ms grace period):**
- On `pointerdown`, do NOT immediately commit to "interact" mode.
- Start a timer (~100ms). If a second pointer arrives within that window, switch to pan/zoom mode and cancel any started interaction.
- If the timer expires with only 1 pointer, commit to interact mode and forward the original event.
- Expose a callback or event system so gm.ts and player.ts can hook into the "interaction confirmed" event rather than raw `pointerdown`.

**Transform application:**
- Set `wrapper.style.transform = translate(${panX}px, ${panY}px) scale(${scale})` and `wrapper.style.transformOrigin = '0 0'`.
- `screenToImage()` must invert this transform: subtract container offset, subtract pan, divide by (baseScale * zoomScale), multiply by image pixel ratio.

### 2. Update canvas.ts

- Remove the fixed scale computation from `sizeAll()`. Instead, size the wrapper to the full image dimensions and let the viewport module handle the visual scaling.
- Actually, keep `sizeAll()` setting canvas pixel dimensions to imgW × imgH, but change the wrapper sizing: set wrapper width/height to image dimensions (not scaled). The viewport's CSS transform will handle fitting.
- Remove `screenToImage()` from the CanvasController interface — it moves to the viewport module.
- Export `getWrapper()` and `getImageSize()` so the viewport can use them.

### 3. Update tokens.ts

- Remove the internal `screenToImage()` and `getScale()` functions.
- Accept a `screenToImage` function as a parameter (injected from the viewport module).
- Drag hit-testing and position updates must use the viewport's `screenToImage()`.

### 4. Update gm.ts

- Create viewport instance, attach to `canvasArea` and `canvasCtrl.getWrapper()`.
- Replace direct `pointerdown`/`pointermove`/`pointerup` handlers on `eventTarget` with viewport-mediated interaction events.
- Use viewport's `screenToImage()` for stroke coordinate calculation.
- On viewport change (zoom/pan), no re-render needed (CSS transform handles it).
- When image loads or switches, call `viewport.resetView()`.

### 5. Update player.ts

- Same viewport integration as GM. Create viewport, attach, use for token drag coordinates.
- Call `viewport.resetView()` on image load/switch.

### 6. Update CSS

- Add `touch-action: none` to `#canvas-area` to prevent browser default touch handling (scroll, zoom).
- Add `will-change: transform` to the canvas wrapper for GPU-accelerated transforms.

## Constraints

- `bun run build` must pass.
- Do not modify files outside the Modifies and Creates lists.
- The viewport module must not import from canvas.ts or tokens.ts — it is a dependency, not a dependent.
- All existing fog brush and token drag functionality must work correctly at any zoom/pan level.
- No JavaScript-based canvas re-rendering on zoom/pan — use CSS transforms only for smooth 60fps.

## Failure Modes

- **screenToImage returns wrong coordinates at non-1x zoom**: strokes land offset from cursor. Detection: zoom to 2x, draw a stroke, verify it lands under the cursor.
- **Touch grace period too long**: 200ms+ delay feels laggy on draw start. Detection: time from finger-down to first visible stroke. Keep at ~100ms.
- **Touch grace period too short**: second finger arrives after window, starts drawing instead of panning. Detection: try to pan with two fingers rapidly.
- **Pan allows losing the map offscreen**: user pans the map entirely out of view. Detection: pan aggressively in one direction, verify clamping.
- **CSS transform causes blurry rendering at high zoom**: canvas pixels become interpolated. Mitigation: set `image-rendering: pixelated` on canvases only if desired, or accept standard bilinear interpolation.
