# Redesign GM and Player UI with floating controls

## Outcome

Both GM and Player pages use a fullscreen canvas layout with floating, translucent, Miro-style controls. The GM has a player presence avatar stack in the topbar, a collapsible right-side map panel, a mode toggle pill, and a vertical brush size slider on the left edge. The Player has near-zero UI — just a corner name indicator. Both layouts work on desktop and tablet. The overall look is cohesive, modern, and unobtrusive, matching the design intent in DESIGN.md.

## Values

1. Design fidelity — match DESIGN.md exactly. Floating controls, translucent, edges only, 44pt tap targets.
2. Touch-friendly — all interactive elements meet 44pt minimum tap target. No controls in canvas center.
3. Canvas maximization — the map fills the viewport. Controls overlay, never push the canvas.
4. Cohesion — GM and Player share the same visual language (colors, blur, roundness, transitions).

## Context

- `DESIGN.md` — full design specification. Key sections: Layout: GM, Layout: Player, Visual Language, Collapse Behavior. Controls collapse to icons on user action, never auto-hide.
- `public/gm.html` — current 3-column grid layout with sidebar-left (brush controls), topbar (name + invite), sidebar-right (gallery + upload). Must be restructured to fullscreen canvas + floating overlays.
- `public/player.html` — current 2-row grid layout with topbar. Must become fullscreen canvas + corner indicator.
- `public/css/style.css` — current styles for grid layout, sidebars, topbar, gallery items, control groups, mode buttons, upload row, player info, toast. Must be rewritten for floating layout.
- `public/js/gm.ts` — DOM element references target sidebar elements by ID. Must be updated for new DOM structure. Event handlers for brush controls, mode buttons, gallery, upload stay the same logically but target new elements. After wu-11, gm.ts stores a `player:roster` array — this WU renders it as the avatar stack.
- `public/js/player.ts` — DOM references are simple. Player info dot/name creation needs to target new corner element. After wu-11, player.ts handles removal notification — this WU styles the removal message.
- `public/js/viewport.ts` — (created by wu-10) handles pan/zoom. The floating controls must not interfere with viewport gestures. Controls need `touch-action: auto` to allow normal button taps while the canvas has `touch-action: none`.

- `#map-panel-toggle`: fixed right edge, vertically centered. 44×44px icon button. Contains a gallery/image SVG icon.

**Player layout:**
- `body.player`: no grid. `#canvas-area` is `position: fixed; inset: 0;`
- `#player-badge`: fixed top-left, small translucent pill. Contains player dot + name.
- No topbar — adventure name shown in document title only.

**Shared styles:**
- `.floating-panel`: base for slide-out panels (map panel).
- Gallery items (`.gallery-item`): keep existing thumbnail styling but adapt to new panel width.
- `.toast`: keep existing styles, ensure z-index above floating controls.
- Mode buttons inside `#mode-toggle`: segmented pill style. Remove `.mode-buttons` wrapper class, style buttons directly.
- Brush size slider: style the thumb to be at least 44px for touch. Use `-webkit-appearance: slider-vertical` or `writing-mode: vertical-lr` for vertical orientation.
- All tap targets: minimum 44px in both dimensions.

**Visual language (from DESIGN.md):**
- Background: `#0d0d1a`
- Controls: translucent with `backdrop-filter: blur(8px)`, 60% opacity background

- Transitions: 200ms ease-out

**Remove**: all `body.gm` grid rules, `#sidebar-left`, `#sidebar-right`, `.control-group`, old fixed-sidebar styles. Keep `.home-*` styles untouched.

### 4. Player presence avatar stack (GM topbar)

Render the `player:roster` data (from wu-11) as a Miro-style avatar stack in `#player-presence`:

**Visual design:**
- Overlapping colored circles (32px diameter, -8px margin-left for overlap after the first).
- Each circle: player's chosen color fill, first letter of name as white text, centered.
- Online players: 2px solid green (`#22c55e`) ring around the circle.
- Offline players: no ring, slightly reduced opacity (0.5).
- If more than 4 players: show first 3 circles + a `+N` overflow counter circle (gray background, white text).
- Circles are ordered: online players first, then offline.

**Popover on click:**
- Clicking any avatar circle opens a small popover below the avatar stack.
- Popover lists all players: colored dot + name + online/offline indicator.
- Each player row has a "Copy link" button and a "Remove" button (trash icon).
- "Copy link" copies the adventure's player invite URL to clipboard.
- "Remove" sends `player:remove` message via WebSocket with the player's tokenId.
- Popover closes on click outside.
- Same translucent/blur style as other floating controls.

**Rendering function in gm.ts:**
```typescript
function renderPresence(roster: Array<{tokenId: string, name: string, color: string, online: boolean}>) { ... }
```
Call this on `player:roster` message and on initial `joined` message.

## Failure Modes

- **Floating controls intercept canvas gestures**: controls block pan/zoom underneath them. Detection: try to start a pan gesture from on top of a control. Fix: controls have `pointer-events: auto` (they consume their own events), but the canvas area behind them naturally doesn't receive those events — this is correct behavior.
- **Vertical slider doesn't work on Safari/iOS**: `-webkit-appearance: slider-vertical` is non-standard. Detection: test on Safari. Fix: use `writing-mode: vertical-lr; direction: rtl;` as a cross-browser alternative.
- **Map panel overlaps content at narrow widths**: 200px panel on a 320px phone screen. Detection: resize browser to 320px. Fix: on screens < 500px, panel should be full-width bottom sheet instead. Or accept that GM-on-phone is not a goal (per DESIGN.md).
- **Blur performance on low-end tablets**: `backdrop-filter: blur()` can be expensive. Detection: test on older iPad. Fix: reduce blur radius or remove blur on `prefers-reduced-motion`.
- **Avatar stack overflow on many players**: 10+ players overflow the topbar. Detection: join 10 players. Fix: overflow counter (+N) limits visible circles to 3-4.
- **Popover positioned off-screen on narrow viewports**: popover extends past right edge. Detection: resize to 600px, open popover. Fix: anchor popover to right edge of topbar, not to avatar position.
