# Fix fog mask persistence on reload

## Outcome

GM reveals areas on a map, reloads the page (or closes and reopens the browser), and sees the same revealed areas. Players who join or rejoin also see the persisted fog state. No fog data is lost across page reloads, server restarts, or reconnections.

## Values

1. Correctness — fog state must survive any combination of reload, reconnect, and server restart.
2. No data loss — when in doubt, save more often rather than risk losing strokes.
3. Backward compatibility — existing adventures with broken 0x0 dimension images must be repaired, not ignored.

## Context

- `src/ws/handler.ts` — fog mask in-memory cache (`fogMaskCache`), `scheduleSave()` debounces writes at 1000ms (line 42), `getFogMaskForImage()` checks cache then DB (line 21-33). The cache is lost on server restart; if the debounced save hasn't fired, fog data is lost.
- `src/fog/serialize.ts` — `serializeMask()` writes width/height as uint32 BE header + deflate-compressed pixel data. `loadFogMask()` reads from DB, `saveFogMask()` writes to DB. If image dimensions are 0x0, the serialized mask has a 0x0 header.
- `src/fog/mask.ts` — `createMask(width, height)` creates a fully-fogged mask. If width/height are 0, the mask is empty (0-length Uint8Array).
- `src/db/images.ts` — `updateFogMask()` writes BLOB to DB. `getImage()` returns the image record including `width` and `height`.
- `src/routes.ts` — `parseImageDimensions()` (line 19-47) extracts dimensions from PNG/JPEG. Returns `{width: 0, height: 0}` for unsupported formats (WebP, etc.) and when parsing fails. Commit `722369b` fixed this but images uploaded before the fix still have 0x0 in the DB.
- `public/js/canvas.ts` — `applyFogMask()` (line 117-139) reads width/height from the mask header. If either is 0, it bails out (line 124-127), keeping fog fully opaque — this silently discards valid fog data when dimensions are broken.
- `src/db/schema.ts` — `images` table has `width INTEGER NOT NULL, height INTEGER NOT NULL`.
- `test/fog/serialize.test.ts` — existing serialization round-trip tests.
- `test/ws/handler.test.ts` — existing WS handler tests including "Late joiner receives current fog state" (line 373).

## Requirements

### 1. Flush fog cache on disconnect and before server shutdown

In `src/ws/handler.ts`:
- When a `close` event fires for a GM connection, immediately flush any pending save timer for all images that GM was editing. Call `saveFogMask()` synchronously (don't just schedule). This ensures that if the GM closes the tab, the debounced save doesn't get lost.
- Export a `flushAllFogCaches(db)` function that iterates `fogMaskCache`, saves every dirty entry to DB, and clears all timers. This is for server shutdown hooks.

### 2. Flush on server shutdown

In the server entry point (`src/index.ts`), register `process.on('SIGINT')` and `process.on('SIGTERM')` handlers that call `flushAllFogCaches(db)` before exiting. This prevents fog loss on server restart.

### 3. Repair 0x0 dimension images on load

In `src/routes.ts` or `src/db/images.ts`, add a function `repairImageDimensions(db, imageId, uploadsDir)` that:
- Reads the image file from disk.
- Parses dimensions using `parseImageDimensions()`.
- If the DB has width=0 or height=0 and the parsed dimensions are valid, updates the DB record.

In `getFogMaskForImage()` in `src/ws/handler.ts`: when `getImage()` returns width=0 or height=0, attempt repair before creating a new mask. This ensures old images self-heal on first access.

### 4. Handle 0x0 masks gracefully on the client

In `public/js/canvas.ts` `applyFogMask()`: when w=0 or h=0 in the mask header, log a warning but use the current `imgW`/`imgH` (from the loaded image) as the dimensions instead of bailing out. Attempt decompression with these dimensions. Only bail out if no image is loaded yet (imgW === 0).

### 5. Reduce save debounce to 500ms

In `src/ws/handler.ts`, reduce the debounce timeout from 1000ms to 500ms. The 1-second window is unnecessarily long for the amount of data being saved (a single DB write of compressed bytes). 500ms still coalesces rapid strokes but halves the data-loss window.

### 6. Test coverage

Add tests to `test/ws/handler.test.ts`:
- "Fog mask persists across GM reconnection": GM draws strokes, disconnects, reconnects, receives the same fog state.
- "Fog mask survives flush": Call `flushAllFogCaches()`, verify fog mask is in DB.

Add tests to `test/fog/serialize.test.ts`:
- "Round-trip with valid dimensions": serialize → deserialize, verify equality.
- "Deserialize rejects 0x0 header": verify error or graceful fallback.

## Failure Modes

- **Save timer fires after server process exits**: fog data lost for last second of strokes. Detection: draw strokes, kill server immediately, restart, check if fog is reset. Fixed by flush-on-shutdown.
- **0x0 images cause createMask(0, 0)**: produces empty Uint8Array, serializes to 0-byte mask, client gets 0x0 header and bails. Detection: upload image with unsupported format, draw fog, reload. Fixed by dimension repair.
- **Client bails on 0x0 mask silently**: user sees fully fogged map after reload with no error. Detection: check browser console for warnings. Fixed by using loaded image dimensions as fallback.
