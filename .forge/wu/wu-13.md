# Add undo and redo for fog strokes

## Outcome

GM can undo and redo fog strokes. Two icon buttons (undo / redo) appear in the bottom-left control cluster next to the mode toggle. Keyboard shortcuts ctrl+z (undo) and ctrl+y / ctrl+shift+z (redo) also work. Each undo reverses one complete brush stroke (pointer-down to pointer-up). Undo/redo state is per-map and resets when switching maps. Players see the undo/redo results in real-time.

## Values

1. Correctness — undo must restore exact previous fog state. No visual glitches or partial undo.
2. Simplicity — stroke-level granularity (one pointer-down to pointer-up = one undoable action), not individual point-level.
3. Performance — replaying stroke history must be fast enough to feel instant (<100ms for typical history depth).

## Context

- `public/js/gm.ts` — brush interaction handlers (lines 199-231). `pointerdown` starts a stroke, `pointermove` adds points, `pointerup`/`pointerleave` ends it. The `pending[]` array collects strokes within a single drag. A "brush action" = all strokes from `pointerdown` to `pointerup`.
- `public/js/canvas.ts` — `applyStroke()` draws directly on fogCanvas using compositing. `applyFogMask(base64)` replays a full fog mask from the server. `loadImage()` clears and re-fills fog. There is no way to "unapply" a stroke — undo requires replaying the mask + all strokes except the undone ones.
- `src/ws/handler.ts` — `fog:stroke` and `fog:stroke:batch` handlers apply strokes to the in-memory mask and broadcast. For undo, the server needs a new message type to reset the fog mask to a prior state.
- `src/fog/mask.ts` — `createMask()`, `applyStroke()`, `applyStrokes()`. Pure functions on `FogMask` (Uint8Array). Replaying strokes server-side is cheap.
- `src/ws/messages.ts` — message parsing/serialization. Needs new message types.
- `public/css/style.css` — after wu-10, the mode toggle is a floating pill at bottom-left. Undo/redo buttons should be adjacent.

## Requirements

### 1. Stroke history tracking (client-side, gm.ts)

Maintain two arrays per active map:
- `undoStack: FogStroke[][]` — each entry is a complete brush action (all strokes from one pointerdown→pointerup).
- `redoStack: FogStroke[][]` — populated when undo is performed, cleared when a new stroke is drawn.

On `pointerdown`: start collecting strokes into a `currentAction: FogStroke[]`.
On `pointerup`: push `currentAction` to `undoStack`, clear `redoStack` (new action invalidates redo).
On map switch: reset both stacks.

Max history depth: 50 actions. When exceeding 50, drop the oldest entry.

### 2. Undo operation

When undo is triggered:
1. Pop the last entry from `undoStack`, push it to `redoStack`.
2. Send a `fog:undo` message to the server containing all strokes from the remaining `undoStack` (flattened).
3. The server receives `fog:undo`, replays all provided strokes on a fresh mask for the active image, saves the result, and broadcasts a `fog:reset` message with the new full fog mask (base64).
4. All clients (including the GM) receive `fog:reset` and call `canvasCtrl.applyFogMask()`.

**Why replay instead of storing snapshots:** fog masks can be large (4000×3000 = 12MB uncompressed). Storing snapshots per action would consume too much memory. Replaying strokes on a fresh mask is fast (pure Uint8Array operations) and exact.

### 3. Redo operation

When redo is triggered:
1. Pop the last entry from `redoStack`, push it to `undoStack`.
2. Send `fog:undo` with the updated full `undoStack` strokes (same mechanism as undo — the server just replays the full history).
3. Server replays, broadcasts `fog:reset`.

### 4. Server-side `fog:undo` handler (src/ws/handler.ts)

New message type `fog:undo`:
```typescript
{
  type: 'fog:undo',
  strokes: FogStroke[]  // flattened list of ALL strokes to replay
}
```

Handler:
1. Validate GM role and active image.
2. Create a fresh mask (`createMask(width, height)`) for the active image.
3. Apply all provided strokes with `applyStrokes()`.
4. Replace the fog mask cache entry for this image.
5. Schedule save (same debounce as normal strokes).
6. Serialize the new mask to base64.
7. Broadcast `fog:reset` to all clients (including sender):
```typescript
{
  type: 'fog:reset',
  imageId: string,
  fogMask: string  // base64
}
```

Add `fog:undo` to the message parser in `src/ws/messages.ts`.

### 5. Client-side `fog:reset` handler

In `gm.ts`: add handler for `fog:reset` — call `canvasCtrl.applyFogMask(msg.fogMask)` if `msg.imageId` matches active image.

In `player.ts`: already has a `fog:reset` handler (line 117-121). Verify it works with this new usage.

### 6. UI buttons (gm.html + style.css)

Add two icon buttons adjacent to the mode toggle in the bottom-left cluster:

```html
<div id="fog-controls" class="floating-control">
  <button id="undo-btn" aria-label="Undo" disabled>↩</button>
  <button id="redo-btn" aria-label="Redo" disabled>↪</button>
  <button id="mode-reveal" class="active">Reveal</button>
  <button id="mode-fog">Re-fog</button>
</div>
```

- Undo/redo buttons are disabled when their respective stacks are empty.
- Use simple arrow characters (↩ / ↪) or inline SVG icons. No external icon library.
- Same 44pt minimum tap target as mode buttons.
- Same translucent floating style.

### 7. Keyboard shortcuts (gm.ts)

- `Ctrl+Z` (or `Cmd+Z` on Mac): trigger undo.
- `Ctrl+Y` or `Ctrl+Shift+Z` (or `Cmd+Shift+Z`): trigger redo.
- Only active when the GM page is focused. Check `ev.metaKey` for Mac support.

### 8. Button state management

After each undo/redo/draw action, update button disabled state:
- `undoBtn.disabled = undoStack.length === 0`
- `redoBtn.disabled = redoStack.length === 0`

## Failure Modes

- **Replay produces different result than original**: floating point or ordering differences in stroke application. Detection: draw, undo, redo — compare fog visually. Mitigation: strokes use integer pixel operations in mask.ts, so replay is deterministic.
- **Large history causes slow undo**: 50 actions × hundreds of strokes per action = thousands of strokes to replay. Detection: time the undo operation. Mitigation: `applyStrokes()` is O(n) over Uint8Array — 10,000 strokes on a 4000×3000 mask takes <50ms in Bun.
- **fog:undo sends massive payload**: flattened stroke array could be large. Detection: monitor WS message size. Mitigation: 50 actions × ~100 strokes × ~40 bytes each ≈ 200KB — acceptable for WebSocket.
- **Redo stack not cleared on new draw**: user draws, undoes, draws again, then redo replays the wrong strokes. Detection: draw → undo → draw new → redo should be disabled. Fix: clear redoStack on every new brush action.
