# Add Docker and deployment config

## Outcome
`docker build -t fogofwar .` produces a working container image. `docker compose up` starts the app with persistent storage for the database and uploaded images. The container serves the app on port 3000, survives restarts without data loss, and responds to health checks. `bun test` exits 0. `docker build` exits 0.

## Values
1. Reliability — data must persist across container restarts.
2. Simplicity — single container, no orchestration complexity.
3. Portability — runs on any machine with Docker installed.

## Context
- `src/index.ts` — entry point, `Bun.serve()` on `process.env.PORT || 3000`.
- `package.json` — scripts: `dev`, `start`, `test`, `build:client`.
- `public/` — static frontend assets.
- `public/dist/` — bundled client JS (generated by `build:client`).
- `data/` — runtime directory for SQLite database and uploaded images. Must be mounted as a volume.
- `data/fogofwar.db` — SQLite database file.
- `data/uploads/` — uploaded map images.
- The app has zero npm dependencies — only Bun built-ins.
- Health check endpoint: `GET /api/health` returns `{"status":"ok"}`.

## Creates
- `Dockerfile` — multi-stage build: install Bun, build client, run server.
- `docker-compose.yml` — single service with volume mounts.
- `.dockerignore` — exclude node_modules, data, .git, .forge.
- `.gitignore` — exclude data/, public/dist/, node_modules/, *.db.

## Modifies
None.

## Requirements

### 1. Dockerfile
Multi-stage build for minimal image size:

**Stage 1: Build**
- Base image: `oven/bun:latest` (or a specific stable version like `oven/bun:1`).
- Copy `package.json`, `tsconfig.json`, `src/`, `public/` (excluding `public/dist/`).
- Run `bun run build:client` to generate `public/dist/`.

**Stage 2: Runtime**
- Base image: `oven/bun:latest` (slim if available, otherwise same as build).
- Copy from build stage: `src/`, `public/` (including generated `dist/`), `package.json`, `tsconfig.json`.
- Create `/app/data` directory with appropriate permissions.
- Expose port 3000.
- Volume: `/app/data`.
- Health check: `CMD curl -f http://localhost:3000/api/health || exit 1` — or use `bun` to make an HTTP request if curl is not in the image. Alternative: use Bun to fetch: `HEALTHCHECK CMD bun -e "fetch('http://localhost:3000/api/health').then(r => process.exit(r.ok ? 0 : 1))"`.
- Entrypoint: `bun run src/index.ts`.

### 2. docker-compose.yml
```yaml
services:
  fogofwar:
    build: .
    ports:
      - "${PORT:-3000}:3000"
    volumes:
      - fogofwar-data:/app/data
    environment:
      - PORT=3000
    restart: unless-stopped

volumes:
  fogofwar-data:
```

### 5. Environment variables
The app should respect:
- `PORT` — server port (default: 3000).
- `DATA_DIR` — path to data directory (default: `./data`). In Docker, this is `/app/data`.

Update `src/index.ts` and `src/db/database.ts` to read `DATA_DIR` from environment if not already doing so. If they already use `./data` hardcoded, make it configurable via `process.env.DATA_DIR || './data'`.

## Constraints
- `bun test` must pass.
- `docker build -t fogofwar .` must succeed.
- Do not modify files outside the Creates list unless strictly required (the exception: if `DATA_DIR` env var support requires a small change to `src/index.ts` or `src/db/database.ts`, that is acceptable).
- No additional runtime dependencies in the container — Bun only.
- Container must run as non-root user if the base image supports it.

## Failure Modes
- **Data loss on container restart:** Volume not mounted → SQLite DB and uploads lost. Detection: docker-compose.yml defines a named volume.
- **Permission denied on volume mount:** Container user can't write to mounted volume. Detection: test `docker compose up` and upload an image.
- **Health check uses curl but curl not in image:** Bun images may not include curl. Use Bun for health check instead. Detection: docker build and run health check.
- **Client JS not included in image:** `build:client` not run during build → 404 on JS files. Detection: build stage runs `bun run build:client`.

## Verification
```bash
bun test
docker build -t fogofwar .
docker run --rm -p 3000:3000 fogofwar &
sleep 2
curl -s http://localhost:3000/api/health | grep -q '"status":"ok"'
kill %1
```
