# Redesign home page with matching visual language

## Outcome

The home page (create adventure / join adventure) uses the same floating, translucent, Miro-style visual language as the GM and Player pages. The page feels like it belongs to the same app. Forms are clean, touch-friendly (44pt tap targets), and work well on mobile. The overall impression is polished and cohesive.

## Values

1. Visual cohesion — same design tokens (colors, blur, roundness, transitions) as GM/Player views.
2. Touch-friendly — all inputs and buttons meet 44pt minimum tap target height.
3. Simplicity — it's still just two forms. Don't over-design.

## Context

- `DESIGN.md` — visual language table: background `#0d0d1a`, controls translucent with `backdrop-filter: blur(8px)`, accent `#4a4aff`, border-radius 8px, transitions 200ms ease-out, tap targets 44pt minimum.
- `public/index.html` — two form sections (`.card`): create adventure (name + password + submit) and join adventure (invite code + name + color picker + submit). Inline `<script>` handles form submission. The script must not change.
- `public/css/style.css` — home page styles at lines 12-51: `.home-main` (max-width 480px, centered), `.card` (background `#1a1a2e`, border `#2a2a4a`, border-radius 8px, padding 1.5rem), inputs and buttons with accent color. These styles need updating to match the new visual language.
- After wu-10, the CSS has the `.floating-control` class and the translucent/blur patterns established. The home page should reuse these visual tokens but doesn't need the `.floating-control` positioning (home page is not a canvas overlay).

## Requirements

### 1. Update card styling

Replace the current `.card` style with the translucent/blur treatment:
- Background: `rgba(26, 26, 46, 0.6)` (same as floating controls).
- `backdrop-filter: blur(8px)` and `-webkit-backdrop-filter: blur(8px)`.
- Border: `1px solid rgba(42, 42, 74, 0.5)`.
- Border-radius: `12px` (slightly more rounded than controls since cards are larger).
- Padding: `1.5rem` (keep current).
- Add a subtle box-shadow for depth: `0 4px 24px rgba(0, 0, 0, 0.3)`.

### 2. Update input styling

- Input fields: height at least 44px (padding to achieve this). Background: `rgba(13, 13, 26, 0.8)`. Border: `1px solid rgba(42, 42, 74, 0.6)`. Border-radius: 8px. Font size: 1rem.
- Focus state: border-color transitions to accent `#4a4aff`, subtle glow `box-shadow: 0 0 0 2px rgba(74, 74, 255, 0.3)`.
- Color input: height 44px, width 44px or wider, border-radius 8px.

### 3. Update button styling

- Buttons: height at least 44px. Background: `#4a4aff`. Border-radius: 8px. Font-weight: 600.
- Hover: `#3333cc` (keep current).
- Active/pressed: scale down slightly `transform: scale(0.98)` for tactile feedback.
- Transition: 200ms ease-out on background-color and transform.

### 4. Update page structure

- Add a subtle app logo or icon above the title (optional — only if it can be done with CSS/SVG, no image file). If not trivial, skip.
- Section headings (`h2`): slightly larger, use accent color or white, letter-spacing for refinement.
- Error text: keep red `#e74c3c`, add an icon or left-border indicator for visibility.
- The overall page should feel like a glass card floating on a dark background — consistent with the floating control aesthetic.

### 5. Responsive adjustments

- On screens < 400px: reduce padding to 1rem, cards go edge-to-edge with small margin.
- Labels: ensure they are readable on small screens (font-size at least 0.85rem, proper contrast).

### 6. HTML changes

Only minor structural changes allowed:
- Add a `<meta name="theme-color" content="#0d0d1a">` if not present (for mobile browser chrome).
- Add appropriate `autocomplete` attributes to form inputs for mobile usability.
- Do not change the inline `<script>` logic.

## Constraints

- `bun run build` must pass.
- Do not modify files outside the Modifies list.
- Do not change form submission logic or API calls.
- Do not add external dependencies (no CSS frameworks, no font imports).
- GM and Player page styles must not be affected by home page CSS changes.

## Failure Modes

- **Blur not supported on older browsers**: home page cards appear fully transparent or invisible. Detection: test in browser without backdrop-filter support. Fix: add a solid fallback background with `@supports not (backdrop-filter: blur(8px))`.
- **Input fields too small on mobile**: fields below 44px cause tap frustration. Detection: inspect computed height on mobile viewport. Fix: explicit `min-height: 44px` on inputs and buttons.
- **Color picker too small**: the native color input renders tiny on some browsers. Detection: test across Chrome, Firefox, Safari. Fix: set explicit width/height and override browser defaults.
