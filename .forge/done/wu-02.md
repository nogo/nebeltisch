# Add image upload and adventure REST API

## Outcome
GM can create an adventure via `POST /api/adventures`, upload map images via `POST /api/adventures/:id/images` (multipart/form-data), list images via `GET /api/adventures/:id/images`, switch the active map via `PUT /api/adventures/:id/active-image`, and retrieve adventure info via `GET /api/adventures/:id`. Uploaded images are stored on disk and served statically. All endpoints validate input and return appropriate HTTP status codes. `bun test` exits 0.

## Values
1. Correctness — uploads must persist, validation must reject bad input.
2. Simplicity — plain `Request`/`Response` handling, no middleware abstractions.
3. Testability — integration tests spin up a real server on a random port.

## Context
- `src/index.ts` — entry point with `Bun.serve()`, fetch handler dispatches to routes.
- `src/routes.ts` — HTTP route dispatcher (switch on pathname). Extend this with new routes.
- `src/db/database.ts` — `initDatabase()` returns a `Database` instance.
- `src/db/adventures.ts` — adventure CRUD: `createAdventure`, `getAdventure`, `getAdventureByPlayerLink`, `setActiveImage`, `deleteAdventure`.
- `src/db/images.ts` — image CRUD: `createImageRecord`, `getImagesByAdventure`, `getImage`, `updateFogMask`, `deleteImage`.
- `src/types.ts` — shared TypeScript interfaces for Adventure, ImageRecord, Token.
- Uploaded images are stored in `./data/uploads/` directory.
- Images are served statically at `/uploads/:filename`.

## Creates
- `test/api/adventures.test.ts` — integration tests for adventure endpoints.
- `test/api/images.test.ts` — integration tests for image upload and listing.
- `test/helpers.ts` — test helper: `startTestServer()` that starts the server on a random port with an in-memory DB, returns `{ url, server, db, stop() }`.

## Modifies
- `src/routes.ts` — add API route handlers for adventures and images.
- `src/index.ts` — ensure uploads directory exists, pass db to route handler, serve `/uploads/*` files.

## Requirements

### 1. Test helper
`startTestServer()` in `test/helpers.ts`:
- Creates in-memory SQLite database with schema.
- Creates `./data/test-uploads-{random}/` temp directory for uploads.
- Starts `Bun.serve()` on port 0 (OS-assigned random port).
- Returns `{ url: string, server: Server, db: Database, uploadsDir: string, stop(): void }`.
- `stop()` closes server and removes temp uploads directory.

### 2. Adventure endpoints

**POST /api/adventures**
- Body: JSON `{ "name": string, "gmPassword": string }`
- Validates: name non-empty, gmPassword non-empty. Returns 400 with `{ "error": "..." }` on bad input.
- Returns 201 with the full adventure object including `playerLink`.
- Content-Type: `application/json`.

**GET /api/adventures/:id**
- Requires `X-GM-Password` header matching `gm_password`.
- Returns 404 if adventure doesn't exist.
- Returns 401 if password wrong.
- Returns 200 with adventure object.

**GET /api/adventures/join/:playerLink**
- Returns 404 if player link doesn't exist.
- Returns 200 with `{ id, name, activeImageId }` (no password or GM details).

### 3. Image endpoints

**POST /api/adventures/:id/images**
- Requires `X-GM-Password` header.
- Body: multipart/form-data with a `file` field (image file).
- Validates: file exists, file is an image (check MIME type starts with `image/`). Returns 400 otherwise.
- Reads image dimensions. Use the image file binary to determine width/height — for PNG, read from the IHDR chunk (bytes 16-23); for JPEG, parse SOF markers. Alternatively, keep it simple: store width=0, height=0 as placeholders and let the client report dimensions on first load. Prefer the simple approach.
- Generates a unique filename: `{uuid}.{extension}`.
- Writes file to `./data/uploads/` (or test uploads dir).
- Creates image record in DB.
- Returns 201 with the image record.

**GET /api/adventures/:id/images**
- Requires `X-GM-Password` header OR valid player link via `X-Player-Link` header.
- Returns 200 with array of image records.

**DELETE /api/adventures/:id/images/:imageId**
- Requires `X-GM-Password` header.
- Deletes file from disk and record from DB.
- Returns 204.

### 4. Active map switching

**PUT /api/adventures/:id/active-image**
- Requires `X-GM-Password` header.
- Body: JSON `{ "imageId": string }` — set to this image. `{ "imageId": null }` — clear active image.
- Validates image belongs to adventure. Returns 400 if not.
- Returns 200 with updated adventure object.

### 5. Static file serving for uploads
Requests to `/uploads/:filename` serve the file from the uploads directory using `Bun.file()`. Return 404 if file doesn't exist.

### 6. Route dispatching
Extend `src/routes.ts` to pattern-match URL paths. Use simple string splitting on `/` segments — no regex library needed. Pass the `Database` instance and uploads directory path to route handlers.

### 7. Tests

**test/api/adventures.test.ts:**
- POST /api/adventures with valid body returns 201 + adventure with id, name, playerLink.
- POST /api/adventures with empty name returns 400.
- GET /api/adventures/:id with correct password returns 200.
- GET /api/adventures/:id with wrong password returns 401.
- GET /api/adventures/:id with unknown id returns 404.
- GET /api/adventures/join/:playerLink returns 200 with limited info.
- PUT active-image updates adventure.

**test/api/images.test.ts:**
- POST upload with a valid image file returns 201 + image record.
- POST upload with no file returns 400.
- GET images list returns uploaded images.
- DELETE image removes file from disk and DB.
- Uploaded file is served at /uploads/:filename.

## Constraints
- `bun test` must pass.
- No npm dependencies.
- Do not modify files outside the Modifies and Creates lists unless strictly required.
- GM password checked via `X-GM-Password` header — simple, no sessions.
- Image files stored as `{uuid}.{ext}` — no user-controlled filenames on disk.

## Failure Modes
- **Path traversal in uploads:** Filenames are server-generated UUIDs — user input never reaches the filesystem path. Detection: test that original filename is stored in DB but not used on disk.
- **Missing uploads directory:** Server must create `data/uploads/` on startup if missing. Detection: test server starts cleanly with empty data dir.
- **File left on disk after DB delete:** `deleteImage` must remove file too. Detection: test checks file doesn't exist after DELETE.
- **Port conflict in tests:** Using port 0 for OS-assigned random port. Detection: tests run in parallel without conflict.
