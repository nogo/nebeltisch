# Build GM frontend with canvas fog

## Outcome
The GM opens the app in a browser, creates an adventure, uploads map images, and sees them rendered on a two-layer HTML5 canvas. A round brush tool erases fog (reveal) or paints fog back (re-fog) with smooth, responsive interaction. A slider controls brush size. The GM sees a sidebar with uploaded images and can switch the active map. Fog strokes are sent over WebSocket in real-time. The UI is functional and minimal — no design polish needed.

## Values
1. Usability — brush interaction must feel instant and natural. No lag between mouse movement and fog change.
2. Simplicity — vanilla TypeScript, no UI framework, minimal CSS.
3. Correctness — fog state on canvas must match the data model.

## Context
- `src/index.ts` — serves static files from `public/` directory and files under `/uploads/`.
- `src/ws/messages.ts` — defines all WebSocket message types (client→server and server→client). The GM client sends `fog:stroke`, `fog:stroke:batch`, `map:switch` messages.
- `src/types.ts` — `FogStroke` interface: `{ x, y, radius, mode: 'reveal' | 'fog' }`.
- `src/fog/mask.ts` — `applyStroke()` logic. The client replicates this locally for instant feedback.
- API endpoints from wu-02: `POST /api/adventures`, `POST /api/adventures/:id/images`, `GET /api/adventures/:id/images`, `PUT /api/adventures/:id/active-image`.
- WebSocket connects to `/ws?adventureId=...&role=gm&password=...`.
- On `joined` message, server sends current fog mask as base64.

## Creates
- `public/index.html` — main page with GM and player entry points.
- `public/gm.html` — GM interface page.
- `public/css/style.css` — minimal shared styles.
- `public/js/gm.ts` — GM client-side logic (will be served as compiled JS).
- `public/js/canvas.ts` — canvas rendering: map image layer, fog layer, brush preview.
- `public/js/websocket.ts` — WebSocket client wrapper: connect, send, receive, reconnect.
- `public/js/api.ts` — REST API client helper functions.

## Modifies
- `src/index.ts` — serve the new HTML pages. If TypeScript files in `public/js/` need to be compiled, use Bun's bundler to build them to `public/dist/` on startup or as a build step. Add a `"build:client"` script to package.json.
- `package.json` — add `"build:client"` script.

## Requirements

### 1. Client build pipeline
The frontend TypeScript files in `public/js/` must be bundled into JavaScript that browsers can execute.

Add to `package.json`:
```json
"build:client": "bun build public/js/gm.ts public/js/player.ts --outdir public/dist --splitting --target browser"
```

Update `"dev"` script to build client first: `"dev": "bun run build:client && bun run --hot src/index.ts"`.

Serve `public/dist/` files and `public/` static files (HTML, CSS). The HTML files reference `dist/gm.js` and `dist/player.js`.

### 2. Landing page (`public/index.html`)
Simple page with two sections:
- **Create Adventure:** Form with adventure name + GM password → POST to `/api/adventures` → redirect to GM page with adventure ID and password in URL fragment (not query params — fragments aren't sent to server).
- **Join Adventure:** Form with player link code + player name + color picker → redirect to player page.

### 3. GM page layout (`public/gm.html`)
- **Top bar:** Adventure name, player invite link (copyable).
- **Main area:** Canvas (takes most of the screen).
- **Left sidebar:** Tool controls — brush size slider (10–200px range), toggle between reveal/re-fog mode, current mode indicator.
- **Right sidebar:** Image gallery — thumbnails of uploaded images, highlight active image, click to switch. Upload button at the bottom (file input).
- Use CSS Grid or Flexbox. No UI framework.

### 4. Canvas rendering (`public/js/canvas.ts`)
Two stacked `<canvas>` elements, same size, absolutely positioned on top of each other:

**Map canvas (bottom):** Renders the current map image. Loaded from `/uploads/:filename`. Scales to fit the container while preserving aspect ratio.

**Fog canvas (top):** Semi-transparent black overlay. Initially fully fogged (filled with `rgba(0, 0, 0, 0.85)`). The eraser reveals by drawing with `globalCompositeOperation = 'destination-out'`. Re-fog by drawing with `globalCompositeOperation = 'source-over'` using the fog color.

Canvas module exports:
- `initCanvas(container: HTMLElement): CanvasController`
- `CanvasController.loadImage(url: string): Promise<void>` — loads map image, resizes canvases.
- `CanvasController.applyFogMask(mask: Uint8Array, width: number, height: number): void` — renders a full fog mask from server state.
- `CanvasController.applyStroke(stroke: FogStroke): void` — applies a single stroke to the fog canvas.
- `CanvasController.clear(): void` — clears both canvases.

**Coordinate mapping:** The canvas may be displayed at a different size than the image's natural dimensions. All fog strokes use image-space coordinates (not screen-space). Convert mouse position to image coordinates using the scale factor.

### 5. Brush interaction
Mouse/pointer events on the fog canvas:

- `pointerdown` — start stroke. Record starting position.
- `pointermove` while pressed — draw fog circle at current position. Send `fog:stroke` message for each position (throttled to max 60 per second to avoid flooding). Apply locally immediately for instant feedback.
- `pointerup` — end stroke. Send any remaining buffered strokes as `fog:stroke:batch`.

Brush preview: while hovering (not pressed), draw a translucent circle outline at the cursor position showing the brush size. Clear and redraw on every `pointermove`. Use a third canvas layer or redraw on the fog canvas and restore.

### 6. WebSocket client (`public/js/websocket.ts`)
- `connectGM(adventureId: string, password: string): WebSocketClient`
- `WebSocketClient.send(msg: ClientMessage): void`
- `WebSocketClient.on(type: string, handler: (msg) => void): void`
- Auto-reconnect on disconnect with exponential backoff (1s, 2s, 4s, max 30s).
- On `joined`: apply fog mask to canvas, render tokens.
- On `fog:stroke` from server (other GM tabs): apply to local canvas.
- On `map:switched`: load new image and fog mask.

### 7. API client (`public/js/api.ts`)
Thin wrappers around `fetch()`:
- `createAdventure(name, password): Promise<Adventure>`
- `uploadImage(adventureId, password, file: File): Promise<ImageRecord>`
- `listImages(adventureId, password): Promise<ImageRecord[]>`
- `deleteImage(adventureId, password, imageId): Promise<void>`
- `switchActiveImage(adventureId, password, imageId): Promise<void>`

### 8. Image gallery sidebar
- On load: fetch image list from API, render thumbnails.
- Click thumbnail: switch active image (API call + WS notification happens server-side).
- Upload button: file input → upload → refresh gallery.
- Active image highlighted with a border.

## Constraints
- `bun test` must still pass (no server-side test breakage).
- No npm dependencies for the frontend. Vanilla TypeScript bundled by Bun.
- Do not modify server-side files outside the Modifies list unless strictly required.
- Fog color: `rgba(0, 0, 0, 0.85)` — slightly transparent so GM can faintly see what's under the fog for positioning.
- Player-facing fog will be fully opaque — that's handled in wu-06.
- Brush size slider range: 10px to 200px in image-space coordinates.
- Canvas must handle images up to 4000x3000 without crashing the browser tab.

## Failure Modes
- **Coordinate mismatch:** If screen-to-image coordinate conversion is wrong, strokes appear in wrong position for players. Detection: manually test by revealing a known landmark and checking player view.
- **Stroke flooding:** Sending a stroke on every pixel of mouse movement overloads WS. Detection: throttle to max 60/s and batch remaining.
- **Memory leak on image switch:** Previous image not garbage collected. Detection: check that old image URL is revoked / canvas cleared before loading new.
- **Canvas scaling artifacts:** Image scaled with CSS but canvas size doesn't match → blurry fog. Detection: set canvas width/height attributes to image natural dimensions, scale with CSS transform.

