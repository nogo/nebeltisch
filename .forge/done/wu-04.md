# Add WebSocket layer and real-time sync

## Outcome
GM and players connect via WebSocket to an adventure room. GM fog strokes are broadcast to all players in real-time. Player token movements are broadcast to all participants. Late joiners receive the current fog mask and all token positions on connect. Only the GM can send fog strokes. Only a token's owner can move it. `bun test` exits 0.

## Values
1. Correctness — messages reach the right clients, role enforcement is strict.
2. Low latency — fog strokes must feel instant for players.
3. Simplicity — Bun native pub/sub, no abstraction layers.

## Requirements

### 1. WebSocket message protocol
All messages are JSON strings with a `type` field. Define these message types:

**Client → Server:**
- `{ type: "join", adventureId: string, role: "gm" | "player", password?: string, playerName?: string, playerColor?: string, playerLink?: string }`
- `{ type: "fog:stroke", stroke: FogStroke }` (GM only)
- `{ type: "fog:stroke:batch", strokes: FogStroke[] }` (GM only — for sending a batch of strokes during continuous drawing)
- `{ type: "token:move", tokenId: string, x: number, y: number }` (owner only)
- `{ type: "map:switch", imageId: string }` (GM only)
- `{ type: "ping" }`

**Server → Client:**
- `{ type: "joined", adventure: { id, name, activeImageId }, tokens: Token[], fogMask: string | null }` — sent on successful join. `fogMask` is base64-encoded serialized mask for the active image, or null if no active image.
- `{ type: "fog:stroke", stroke: FogStroke, imageId: string }` — broadcast to players when GM reveals/re-fogs.
- `{ type: "fog:stroke:batch", strokes: FogStroke[], imageId: string }` — batch broadcast.
- `{ type: "fog:reset", imageId: string, fogMask: string }` — full mask sync (used for late joiners or after map switch). Base64-encoded.
- `{ type: "token:moved", tokenId: string, x: number, y: number }` — broadcast to all.
- `{ type: "token:added", token: Token }` — when a player joins and their token is created.
- `{ type: "token:removed", tokenId: string }` — when a player disconnects.
- `{ type: "map:switched", imageId: string, fogMask: string | null }` — broadcast when GM switches map.
- `{ type: "player:joined", playerName: string, playerColor: string }` — notify others.
- `{ type: "player:left", playerName: string }` — notify others.
- `{ type: "error", message: string }`
- `{ type: "pong" }`

### 2. Connection upgrade and authentication
In the `fetch` handler, when the URL path is `/ws`:
- Parse query params: `adventureId`, `role`, `password` (for GM), `playerLink` (for player), `playerName`, `playerColor`.
- Validate:
  - Adventure exists.
  - If role=gm: password matches `gm_password`.
  - If role=player: `playerLink` matches adventure's `player_link`. `playerName` and `playerColor` are required.
- On success: `server.upgrade(req, { data: { adventureId, role, playerName, playerColor, tokenId } })`.
- On failure: return HTTP 401 or 400 with error message.

For players: on upgrade, create a token in the DB and include `tokenId` in the upgrade data.

### 3. Connection tracking
`src/ws/connections.ts` manages a `Map<WebSocket, ConnectionInfo>`:

```typescript
interface ConnectionInfo {
  adventureId: string;
  role: 'gm' | 'player';
  playerName?: string;
  playerColor?: string;
  tokenId?: string;
}
```

- `registerConnection(ws, info)` — adds to map, subscribes to `adventure:{adventureId}` topic.
- `unregisterConnection(ws)` — removes from map, unsubscribes. If player: delete their token from DB, broadcast `token:removed`.
- `getConnection(ws): ConnectionInfo | undefined`
- `getConnectionsForAdventure(adventureId): ConnectionInfo[]`

### 4. WebSocket handlers in `src/ws/handler.ts`

**open(ws):**
- Connection info is available via `ws.data` (set during upgrade).
- Register connection.
- Subscribe to adventure topic: `ws.subscribe(\`adventure:${adventureId}\`)`.
- Load current state: active image, fog mask for active image, all tokens.
- Send `joined` message with current state.
- Broadcast `player:joined` and `token:added` to other participants.

**message(ws, message):**
- Parse JSON. On parse error, send `error` message.
- Switch on `type`:
  - `fog:stroke` / `fog:stroke:batch`: validate sender is GM. Apply stroke(s) to the in-memory fog mask. Persist to DB (debounced — save after 1 second of no new strokes, not on every single stroke). Publish stroke to adventure topic (excluding sender — `ws.publish` already excludes sender).
  - `token:move`: validate sender owns this token. Update position in DB. Publish `token:moved` to adventure topic.
  - `map:switch`: validate sender is GM. Call `setActiveImage`. Load fog mask for new image. Publish `map:switched` with fog mask to adventure topic.
  - `ping`: send `pong`.

**close(ws):**
- Unregister connection (which handles token cleanup and notifications).

### 5. Fog mask in-memory cache
Keep active fog masks in memory to avoid DB reads on every stroke:

```typescript
const fogMaskCache = new Map<string, FogMask>(); // keyed by imageId
```

- On first access: load from DB. If null, create a fully fogged mask (need image dimensions — get from DB record).
- On stroke: apply to cached mask, schedule debounced DB save.
- On map switch: ensure new active image's mask is loaded.
- Debounced save: after 1 second of no new strokes, serialize and persist to DB. Use `setTimeout` / `clearTimeout`.

### 7. Tests

**test/ws/handler.test.ts:**
Integration tests that start a real server and connect WebSocket clients.

Use the test helper from wu-02 (`startTestServer`) extended to include WebSocket support. Create adventures and images via the REST API first, then test WS behavior.

Helper: `connectWS(url, params): Promise<WebSocket>` — connects and waits for `open` event. `waitForMessage(ws, type, timeout): Promise<message>` — waits for a specific message type.

Tests:
- GM connects with correct password → receives `joined` with adventure info.
- GM connects with wrong password → HTTP 401 on upgrade.
- Player connects with valid player link → receives `joined` with current state + their token.
- Player connects → other connected clients receive `player:joined` and `token:added`.
- GM sends `fog:stroke` → all connected players receive the stroke.
- Player sends `fog:stroke` → receives `error` (role enforcement).
- Player sends `token:move` for their own token → all clients receive `token:moved`.
- Player sends `token:move` for another player's token → receives `error`.
- GM sends `map:switch` → all clients receive `map:switched` with fog mask.
- Player disconnects → other clients receive `player:left` and `token:removed`. Token deleted from DB.
- Late joiner receives current fog state and all existing tokens.
- Ping/pong works.

## Constraints
- `bun test` must pass.
- No npm dependencies.
- Fog mask persistence is debounced — not on every stroke.
- WebSocket messages are JSON strings (not binary). Fog mask snapshots are base64-encoded in JSON.
- Do not modify files outside the Modifies and Creates lists unless strictly required.
- Players cannot perform GM actions. GM actions from player connections must be rejected with an error message.

## Failure Modes
- **Fog mask not persisted on crash:** Debounced save means up to 1 second of strokes can be lost on hard crash. Acceptable for PoC. Detection: test that save eventually happens after strokes stop.
- **Memory leak in fog cache:** Masks stay in memory forever. For PoC with few adventures this is fine. Detection: log cache size.
- **Race condition on fog save:** Single writer (GM) so no real race. Debounce timer ensures only latest mask is saved.
- **Player impersonates GM:** Role is set during upgrade from validated auth — cannot be changed after connection. Detection: test that player fog strokes are rejected.
- **Orphaned tokens on crash:** If server crashes without calling `close`, tokens remain in DB. Acceptable — they'll be cleaned up when the adventure is next loaded.
